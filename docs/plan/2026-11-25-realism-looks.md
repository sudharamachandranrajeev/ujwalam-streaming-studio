# Realism looks: several realism scene types, for live scenes and reels, 2026-11-25

Status: see "User answers" below (user request 2026-11-25: "need multiple type of realism scenes, as for reference if required";
earlier request: "different realistic graphics filters, post processing or reshaders for the reels").

## What exists

- D381 "Make realism scene" (flag `realism-look`, off): one look only (filmic LUT 0.85, sharpen 0.3, vignette 0.25) on
  the game layers of a scene copy. Never checked on real footage; GPU cost next to the three encodes not measured.
- Reels: colour only from Reel styles (a LUT measured from the user's example videos) and the four long-video themes.
- No library of realism looks; no post-processing beyond LUT, sharpen and vignette.

## Proposal

| # | Step | Done when |
|---|------|-----------|
| RL1 | **Look library as data.** `data/looks/<id>.json`: name, what it looks like in plain words, LUT, and a list of per-pixel effects with amounts. Proposed starting set (names and values to be approved): Filmic (today's), Cinematic (teal shadows, warm skin, soft contrast), Natural daylight (true colours, gentle sharpen), Gritty war (low saturation, crushed greens, film grain), Night neon (deep blacks, bloom on lights), HDR vivid (local contrast, high clarity). Each LUT is generated by a committed tool and tested byte for byte, like `realism-filmic.cube`. | Schema test; each look renders on a test frame and its measured colour matches the planned shift. |
| RL2 | **New per-pixel effects** where the look needs them: bloom (bright-pass + blur), film grain, clarity / local contrast, chromatic aberration (small), lens dirt off by default. GPU shaders in the host for live; the same maths in ffmpeg for reels. Flash rule unchanged. | Host shader tests; GPU cost measured next to the three NVENC encodes (budget: under 1 ms per frame per canvas). |
| RL3 | **Studio.** Scene right-click > **Make realism scene** becomes a sub-menu with each look and a small preview swatch. The copy is named "<scene> <look>". Switching a realism scene's look later: Layer effects > Look. The flag `realism-look` turns ON (requested feature). | QML probe; route test that the original scene never changes. |
| RL4 | **Reels.** Settings > Clips > Clip look gets **Realism look**: Off, one look, or Random from the ones you tick, per reel type. Reels render off air, so heavier steps are allowed there: better sharpening and denoise, and optionally a local AI upscale/denoise model (download, only with the user's yes). | Reel renders measured back (colour shift, no flash, one audio stream); render time per minute recorded. |
| RL5 | **From a reference.** "New look from a reference": the user gives a screenshot or short video of a look they like (another game, a film, a ReShade preset screenshot); the colour part is measured with the Reel styles colour analysis (already built) and saved as a new look. Nothing from the reference is copied or posted. | A reference with a known colour cast gives a look that reproduces it within tolerance. |
| RL6 | **Real check** (needs the user): each look on real gameplay, live (GPU cost on the laptop) and on reels; the user keeps, tunes or drops each one. | Evidence with measured GPU cost and the user's choices. |
