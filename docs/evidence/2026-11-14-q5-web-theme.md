# Q5: web control page follows the studio theme

Date: 2026-11-14. Plan step Q5 of `docs/plan/2026-11-11-qml-studio-plan.md`. Branch `ui/q5-web-theme`.

## What

- `services/studio-ui/web-theme.mjs`: turns a studio theme pack (`data/themes/<id>.json`, or a custom pack in the folders below) into the page's `/css/tokens.css`. Standard library only. Every variable of the old static file is kept, plus `--color-accent-hi` and `--color-disabled`.
- The UI server serves that generated file at `/css/tokens.css` only when the new flag `web-theme` ("Web page theme", Appearance page, off by default) is on. It reads the user's choice (`ui.theme` in `settings.json`, the same value the studio saves) on every request, so a theme switch shows on the next page load with no restart. Flag off, or a theme that is missing, broken or whose id differs from its file name: the static `ui/css/tokens.css` is served as before.
- Theme folders searched, first match wins: `UJWALAM_THEMES_DIR`, `%APPDATA%\Ujwalam Studio\themes` (the studio's user themes), repo `data/themes`. The studio also looks in `<app dir>\themes`; the web server cannot know that folder (UNVERIFIED for a packaged install; the repo `data/themes` path is module-relative and may need the same fix there). No saved choice: `violet-night`, as in the studio.
- `ui/css/app.css`: section headings in sentence case at the body size (no capitals, no letter spacing), no letter spacing on the brand name, corner radius from the token everywhere, hover and focus use theme tokens. Tokens only.
- Fonts: names only (family, fallbacks, system-ui). No font file is linked, so no Microsoft font is ever served. Font names are checked against a strict character set, so a custom pack cannot put CSS into the file.
