## What was built

- `data/clip/excitement.json`: marker phrases, voice baseline values, audio-event classes, chat values, weights, ranking
  and live values. Every block is `status: unverified`, except the phrases, which are the user's answer of 2026-11-24
  (`status: user-answer-2026-11-24`).
  - Phrases: `adipoli` (adipoli, adi poli, adipolli; അടിപൊളി), `polich` (polich, pwolich, polichu, pwolichu, polichoo,
    pwolichoo; പൊളിച്ച), `scene` (scene; സീൻ, സീന്), `super` (super, suuper; സൂപ്പർ, സൂപ്പര്).
  - Latin spellings match as whole adjacent words after lower-casing, NFC and folding repeated letters (adipoliii is
    adipoli). Malayalam spellings match as part of a word after NFC, because Malayalam joins endings to the word.
  - Not matched: "superb", "scenery", "politics" and a bare പൊളി.
- `services/clip/excitement.py`, post-stream: an excitement score per second of the recording, from 0 to 1. It combines
  these parts:
  - Loudness rise: RMS dBFS. Pitch rise: autocorrelation over voiced 50 ms frames, median per second. Both are measured
    against the speaker's own rolling baseline: the median/MAD of the earlier voiced seconds, `baselineSec` 600, at
    least `minVoicedSec` 20.
  - Marker phrases from a transcript (`clipper candidates --transcript FILE`).
  - Laughter, shout and cheer from YAMNet, on the CPU only (`CPUExecutionProvider`, 2 intra-op threads, 60 s chunks).
  - The chat rate, from the chat counts the clipper already reads (`clip_signals.read_chat`).
  - The score is a weighted mean over the parts that are available. A missing part is left out, never guessed.
- The model is used only when the download manager has put it in place and its size and SHA-256 equal the pinned item.
  It is re-hashed on each run.
- `services/clip/clipper.py` `cmd_candidates`, through `_excitement`, adds these ranking events:
  - `voice.excitement`: local maxima at or above `rank.threshold`, strength equal to the score, weight
    `rank.excitementWeight`.
  - `voice.phrase`: weight `rank.phraseWeight`.
  - At most one of each kind per 30 s.
- Each candidate gets an `excitement` value (the highest score inside it), for reel cuts. The value does not change
  the order. `candidates.json` gains `signals.excitement` (the parts used, timings and reasons).
- With the flag off, or on any failure, the result is None and the ranking is exactly as before.
- `services/clip/clip_rank.py`: a `voice.phrase` candidate passes `minScore`, like a marker or a chat "clip it".
  User, 2026-11-24: "a marker phrase marks the moment".
- `services/event-core/voice-marks.mjs`, live: `heard(text)` matches the same phrases with the same rule, using the
  shared samples in `tests/fixtures/voice-phrases.json`.
  - A phrase writes one host marker, `marker.add` with source `audio` and note `voice: marker phrase <id>`. The note
    holds no transcript text.
  - Limits: one marker per phrase per 30 s, one marker in total per 5 s, and at most 2 calls in flight.
  - The flag is read on each line. Errors are counted and never thrown.
  - It gets only an `addMarker` link. The host's markers role allows only `marker.add` and `mixer.list`.
- Settings switch: `voice-excitement` in `data/flags.json`, ON (user-requested), page clips, plain-words description.
  Decision entry: D443 T6 in `docs/plan/2026-10-29-v1-decisions.md`.
- Download item `data/downloads/audio-events.json`, described below.

## Open and UNVERIFIED

- **No live transcriber exists in the repo.** The plan's "live CPU Whisper" was not found under `services/`. The live
  audio signal today is only the host meter peak (F6 `live-markers.mjs`, `audio.peak`). Because of that:
  - `voice-marks.mjs` is built and tested, but nothing calls `heard()` yet. Live phrase marks start only when a live
    speech-to-text feed exists.
  - That feed needs mic capture plus a CPU Whisper sidecar, which is its own piece of live-path work: VRAM rule, CPU
    budget, and a review by the strongest model.
  - Live laughter, shout and pitch need raw mic samples, which the event core does not have. Live, only the existing
    loudness peak and chat markers run.
- **Post-stream transcript:** the clipper uses phrases only when `--transcript` is given. The launcher or posting chain
  does not pass a whole-recording transcript yet, because Whisper runs per reel. Phrase scoring on real runs depends on
  that wiring.
- **Reel cuts:** candidates carry `excitement`, and `moment_score()` exists. No reel builder orders its pieces by it
  yet.
- **Mixed track:** post-stream reads audio track `voice.track` 0, which is the mixed stream audio. Game sound raises
  loudness and pitch, so this is not the mic alone. Whether a mic-only track exists in the user's recordings is
  UNVERIFIED.
- **Accuracy on the user's voice and streams** (Malayalam, Manglish, game noise, laughter detection in game audio):
  UNVERIFIED. No user media was used.
- **All values** in `excitement.json`: proposals. These are the weights (loudRise 0.25, pitchRise 0.15, phrase 0.3,
  event 0.2, chat 0.1), the ranking weights (excitement 0.5, phrase 0.8, threshold 0.45), zFull 4, the 600 s baseline,
  event full 0.5, the live gaps 30 s / 5 s and the phrase variants beyond the user's list. They need the user's
  approval.
- **Cost on a long recording:**
  - Decode writes a temporary 16 kHz s16 file into the clip output folder: about 115 MB per hour. It is deleted after
    the run.
  - Pitch runs per second in numpy. Timing on a full recording was not measured.
- **Live is never touched by the post-stream pass:** the post-stream pass runs inside the clipper, which already
  refuses on air. The pass has no extra on-air check of its own.
