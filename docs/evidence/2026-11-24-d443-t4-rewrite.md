# D443 T4: rewrite scheduled posts (and undo)

Date: 2026-11-24. Plan row T4 in `docs/plan/2026-11-24-ai-post-text-voice.md`. Status: built and tested with fakes only; never run against real Google (UNVERIFIED).

## What it does
- `services/posting/rewrite.mjs`: `runRewrite` and `runUndo`. CLI: `node services/posting/cli.mjs youtube rewrite [--only ids]` and `youtube rewrite-undo [--only ids] [--force]`.
- Candidates are only entries in Ujwalam's own posting ledger: status `uploaded`, a `videoId`, and a publish time Google got that is still in the future. Nothing else on the channel is read or written. Public or past items are not candidates (no call at all).
- Per video, cheap local checks first (not already rewritten, text not already AI, not edited by the user, clip file still on disk), then `videos.list part=snippet,status` (1 unit): must still be private, scheduled for the same time, and carry the same title and description Ujwalam uploaded (else `changed-on-youtube`, never overwritten).
- New text: same `withAiText` and checker as the drafts (T2). A template fallback or a failed check SKIPS the video. The AI title replaces the title; AI lines go before the old description (links and credits kept); AI tags go before the old tags, within limits. A placeholder that only the AI text introduces rejects it.
- `videos.update` replaces the whole snippet, so the full original snippet is saved to `<data>/posting/rewrites.json` BEFORE the call (state `pending`, then `rewritten`), and every writable field (title, description, tags, categoryId, defaultLanguage) is sent back. A refused update removes the record.
- One ledger line each in `<data>/posting/rewrite-ledger.jsonl` (`rewrite` or `undo`, video id, units).
- Undo restores the saved original exactly, per item or in bulk; a video edited by hand since the rewrite is left alone unless `--force`. Undo works with the rewrite switch off (it is the way back).
- Quota: `data/posting/quota.json` `updateUnits` 50 (source and UNVERIFIED note in the file) plus 1 unit for the read. Checked before every video; `writeRoom` stops the run before the day's read reserve would be touched and reports how many were left.

## Switch
`post-rewrite-scheduled` in `data/flags.json` (Settings > Posting), default OFF, plain-words description: it changes live platform data, nothing runs on its own.

## Review fixes (independent Opus review)
The Codex review could not run: the account rejects the configured model. An Opus review was done instead; all P1, P2 and P3 #9 findings are fixed, each with a test in `tests/posting-rewrite.test.mjs` (now 23 tests, all pass).
- P1 `defaultAudioLanguage` added to the writable snippet fields (kept by the update, restored by undo).
- P1 An update that fails without a definite 4xx answer (timeout, dropped connection, 5xx) keeps the saved original as `pending` (reported `update-unknown-pending`); only a definite 4xx removes the record. A later rewrite skips it (`pending-unresolved`); undo treats remote == original as already restored.
- P1 Undo (also with `--force`) skips any video that is not private with a future publish time (`now-public`).
- P1 One rewrite or undo at a time: exclusive lock file `<data>/posting/rewrite.lock` (create-exclusive, dead owner's lock taken over, otherwise `busy`). The item's record is re-read right before the pending write, so another run's record is never taken as the original.
- P2 Videos within 30 minutes of publishing are not candidates, and the time is checked again right before the update (generation takes minutes).
- P2 The access token is fetched again for each video.
- P2 Reads inside a rewrite or undo are charged like writes (`reserveWriteRead`), so they cannot use the read reserve.
- P2 Title and description are compared after normalising line endings and trailing spaces (still fail-closed on any other difference). UNVERIFIED which differences real YouTube introduces.
- P3 Ledger entries without a string `sha256` or `target` are ignored.
