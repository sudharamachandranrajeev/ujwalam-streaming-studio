# D443 T3: cover with the AI hook (2026-11-24)

## What changed
- `services/clip/reel_cover.py` (new): one ffmpeg run through the RP6 renderer (`reel_thumbnail.png_argv`, look and font
  from `data/clip/thumbnail.json`): frame at the chosen second, hook as 1-2 centred "main" lines, JPEG (-q:v 2). Hook is
  cleaned like reel titles (upper case, safe characters) and reaches ffmpeg only through text files.
- `services/posting/ai-cover.mjs` (new): `makeHookCover` runs it (repo Python, `-I`, `windowsHide: true`, 150 s deadline);
  true only on exit 0 and a JPEG of at most 2 MB (the thumbnails.set limit). Never throws.
- `services/posting/index.mjs` (`packageUploads`): when the draft used the checked AI text (`textSource: 'ai'`) the cover
  is made from `ai.thumbTime` and `ai.thumbHook` (`opts.coverMaker` seam, default `makeHookCover`). `cover.atSec` = thumbTime;
  `ai.cover` = `hook` or `plain`. Failed render: the plain frame as before. A reel with its own start frame
  (`row.thumbnail === true`, frame 0 already edited) keeps frame 0. Template fallback / flag off: untouched code path.
- Long video: `cover.jpg` already goes to `thumbnails.set` (`youtube.mjs setThumbnail`, best effort, quota counted); it now
  carries the new image. No new Google call was needed. Shorts: first-frame behaviour unchanged for reels with a start frame.
- Flag: reuses `ai-post-text`; its description (data/flags.json) now says in plain words that the cover uses it.
