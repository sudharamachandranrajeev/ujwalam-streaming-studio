# D443 T5: AI caption clean-up (2026-11-24)

## What

After Whisper has made the caption lines of a reel or long video (off air only), the local model tidies the text of each
line: punctuation, casing, one Manglish spelling, game words and the user's cheers ("adipoli", "polich", "pwolich",
"scene", "super") from `data/clip/caption-words.json` (placeholders only). Flag `ai-captions` (Settings > Clips, ON, user-requested,
needs `local-ai-model` and `reel-captions`; decision D443 T5).

Pipeline: `reel_captions.make_transcript(..., clean=flags)` writes `transcript.json`, then `clean_transcript` runs
`node services/local-model/caption-clean.mjs transcript.json --flags=...` (child via `run_tool`, no console window).
The Node side runs one `withModel` batch of its own (separate from the post-text batch: they run at different times,
in the clip worker and in posting) and rewrites `transcript.json`. Because this happens before `retime`, `write_ass`
and `write_subtitles`, the burned-in captions and `captions.srt` / `captions.vtt` all use the cleaned text. Called from
`clipper._caption_reel` (reels, montages) and `long_teaching.batch_overlay` (long video).

## Rules (all enforced in code)

- Timing never changes: cues go out as `{id, text}`; the json_schema forces the same ids (enum, min/max items); the
  returned id set must equal the sent set exactly (no duplicate, no missing) or the whole chunk keeps the originals.
  Only `text` is replaced (`rawText` keeps the Whisper line). Python re-checks start/end of every segment after the
  Node step and restores the file if anything differs.
- Checker `checkCue` (token rule + edit distance): every word of the cleaned line must be a word of the original line,
  a listed word, or within edit distance 2 (1 for words of 4 letters or less) of one; words may grow by at most 20 %
  (min 1) and may not drop below 60 %; the set of scripts must be identical (Malayalam stays Malayalam, no Latin
  added); no line break; limits `clean.maxCueChars` 90 / `maxCueWords` 16 in `data/clip/reel-captions.json`; a profile
  term (data/profile.local.json) not in the original is rejected. New names are caught by the new-word rule. A rejected
  cue keeps the original text.
- Never on air: the runner (`withModel`) refuses on air and stops mid-batch; the CLI then reports `failed`, file untouched.
- Model unavailable or any error: transcript unchanged, `info.clean` records status and reason.
- Flag off (either flag): the step is not run at all (`clean_flags` returns None).

## UNVERIFIED

- Real model quality on the user's voice (Manglish spelling consistency, Malayalam lines): no real model run. Thresholds
  (edit distance 2, 20 % / 60 % word ratios, 90 chars) are first guesses; rejected-cue counts are in `info.clean.rejects`
  to tune from.
- The model sees only the lines, not the audio, so spelling consistency depends on the prompt and the word list.
- Word-by-word highlight: a cleaned line whose words differ from the stored word times falls back to the plain card
  (existing `_words_match` rule), so punctuation changes drop the highlight for that line.
- A whole transcript is cleaned in chunks of 40 cues; a long video makes several calls (timeout 120 s each).
- Real end-to-end run (Python child launching Node and llama-server) not done; the Node call is injected in tests.
